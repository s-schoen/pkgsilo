# AGENTS.md

## Feature structure

Every feature is a vertical slice in `feature/<feature>/`, shaped like `feature/identity/`, the reference slice: read it before building a new feature, and register the new feature as a component in `.github/codecov.yml`. Only features go in `feature/`; shared infrastructure stays in `core/`.

A feature is a directory with three layer packages: `feature/<feature>/api` → `feature/<feature>/service` → `feature/<feature>/repository`. Each layer calls only the layer below and owns its types and errors. The layer above always translates, even when the types are identical today: record → domain model → API response, repository error → domain error → HTTP problem.

Each layer package has the same files:

- `types.go`: the layer's data types. The repository has `<Name>Record` with `db` tags, the service has the domain model, and the API has explicit request and response bodies.
- `errors.go`: the layer's errors, plus `translateError` for the errors of the layer below. In the API, this file holds the problem values and `writeError` instead.
- `repository.go` / `service.go`: the interface and its single implementation. `handler.go` (API) has no interface. A feature that is an authentication method also has `authenticator.go` in its API, implementing `authn.Authenticator`, and `app/app.go` passes it to `authn.Require`.

### Layer rules

- **Repository**: one interface, implemented for PostgreSQL with sqlx. A repository that also runs in a transaction, as in `app.Bootstrap`, takes a `database.Querier`. Each test gets its own fresh database with `migrations/` applied from `databasetest.New(t)` (`test/databasetest`) and calls `t.Parallel()`. Never mock the database.
- **Service**: all logic lives here: IDs, timestamps, audit fields, domain rules. List methods query the repository for `limit+1` rows and return a `pagination.Page` built with `pagination.FromLookahead` (`core/pagination`). Tests mock the repository, check error translation with `servicetest.AssertTranslated` and capture a mock argument whole with `servicetest.Capture` (`test/servicetest`).
- **API**: a chi handler with `Routes()`, mounted under `/api/v1` in `app/app.go`, in the group behind `authn.Require` unless the route is public. Handlers pass `authn.PrincipalFrom(r.Context()).IdentityID` to the service as the actor. Validate all input with ozzo-validation through the shared `core/request` package (`DecodeJSON`, `ParsePagination`). Respond through the `core/envelope` writers (`WriteResource`, `WriteCreated`, `WriteCollection`, `WriteProblem`, and `WriteJSON` only for bodies with a format of their own that is not wrapped in an envelope, such as health checks); a service page becomes a collection with `NewPagedCollection`. Every domain error a client must tell apart gets its own problem type, defined with `envelope.DefineProblemType` in `errors.go`. The generic `about:blank` problems (`envelope.NotFoundProblem`, …) are for problems that mean nothing beyond their status. Tests mock the service, mount the handler with `apitest.Mount`, which authenticates every request as `apitest.Actor`, and send requests through an `apitest.Client` (`test/apitest`), whose `Assert*` methods check responses against the problem values in `errors.go`.

Shared `core` packages log nothing, except `authn.Require`, which logs rejected and failed authentications. Bugs such as an unencodable response or a misconfigured validation rule panic, and the router's recoverer logs them with the request ID. Everything else is logged by the handler through its injected logger.

Translate only errors that have a meaning in the layer above. Wrap every other error with `%w`, so it reaches the API's log intact and is answered with a 500 without details.

### End-to-end tests

Every feature has `feature/<feature>/e2e_test.go` (package `<feature>_test`), which drives the assembled app through `/api/v1` on a real database from `apptest.New(t)` (`test/apptest`), whose client authenticates as the `admin` identity of the first start; `api.Anonymous()` sends no credential. It covers what only the whole app shows: flows across requests, database constraints, Location headers. Each test's doc comment lists its steps in order, each with the result it expects, and numbered comments (`// 1. Create.`) mark where each step starts in the code. Write each expected problem type out as a literal `envelope.DefineProblemType(…)`, so the test pins the public contract (slug, title, status) independently of `errors.go`.

### Test helpers

Shared test helpers live in `test/<name>test`, one package each, so the internal tests of any layer can import them without an import cycle; only `test/apptest` imports `app`. A client reports to the test it was made for: inside a subtest, use `api.For(t)`.

### Mocks

Mocks are generated by mockery into `<pkg>/mocks` and committed. Register each new interface in `.mockery.yml`, then run `task generate`.

## CI and dependency updates

- Run changed workflows locally with `task ci:push` and `task ci:pr` (act) before pushing them.

## Git

- NEVER create git commits or branches on your own unless you're explicitly told so
- Every commit passes the prek hooks (`prek.toml`): when one fails, fix what it reports or stage the files it rewrote, then commit again.
- Write commit messages as Conventional Commits (`type(scope): subject`, as in `git log`); the commit-msg hook rejects anything else.
