# AGENTS.md

## Feature structure

Every feature is a vertical slice shaped like `identity/`, the reference slice: read it before building a new feature.

A feature is a directory with three layer packages: `<feature>/api` → `<feature>/service` → `<feature>/repository`. Each layer calls only the layer below and owns its types and errors. The layer above always translates, even when the types are identical today: record → domain model → API response, repository error → domain error → HTTP problem.

Each layer package has the same files:

- `types.go`: the layer's data types. The repository has `<Name>Record` with `db` tags, the service has the domain model, and the API has explicit request and response bodies.
- `errors.go`: the layer's errors, plus `translateError` for the errors of the layer below. In the API, this file holds the problem values and `writeError` instead.
- `repository.go` / `service.go`: the interface and its single implementation. `handler.go` (API) has no interface.

### Layer rules

- **Repository**: one interface, implemented for PostgreSQL with sqlx. Each test gets its own fresh database with `migrations/` applied from `databasetest.New(t)` (`core/database/databasetest`) and calls `t.Parallel()`. Never mock the database.
- **Service**: all logic lives here: IDs, timestamps, audit fields, domain rules. List methods query the repository for `limit+1` rows and return a `pagination.Page` built with `pagination.FromLookahead` (`core/pagination`). Tests mock the repository.
- **API**: a chi handler with `Routes()`, mounted under `/api/v1` in `cmd/main.go`. Validate all input with ozzo-validation through the shared `core/request` package (`DecodeJSON`, `ParsePagination`). Respond through the `core/envelope` writers (`WriteResource`, `WriteCreated`, `WriteCollection`, `WriteProblem`); a service page becomes a collection with `NewPagedCollection`. Tests mock the service and mount the handler on `router.New` (`core/router`).

Shared `core` packages never log. Bugs such as an unencodable response or a misconfigured validation rule panic, and the router's recoverer logs them with the request ID. Everything else is logged by the handler through its injected logger.

Translate only errors that have a meaning in the layer above. Wrap every other error with `%w`, so it reaches the API's log intact and is answered with a 500 without details.

### Mocks

Mocks are generated by mockery into `<pkg>/mocks` and committed. Register each new interface in `.mockery.yml`, then run `task generate`.
